二、根因链条

点「刷新数据」 └─ loadLiveDatasets() 并发拉取 21 个云端 JSON ├─ matches.json → BUILT_DATA = core ✅ 文件换成最新 │ └─ ❌ 没同步 state.safeParlay（分层串关渲染读的正是 state） │ → 分层串关永远停在页面载入时的深拷贝快照 ├─ score_predict.json → BUILT_SCOREPRED = sp ✅ │ └─ 但该文件由 fetch_scores.py「本地兜底」生成： │ 只重写 matches，❌ dateIndex / dateList 沿用上一轮文件 │ → 「历史回溯」永远停在最后一次跑 FD 主路径的 11-11 └─ ❌ AB_STATS 是 const 构建期常量，且 ab_compare.json 未上云 → A/B 三源命中率区刷新后不更新 附带：0 档时 highOddsSummary 整行空白 → 看不到本批次与评估时间， 用户无法判断「今天到底算没算」，进一步加重「没更新」的观感。

为什么分层串关连续 4 天 0 档不是故障

11-12 批次 4 条候选全不合格：2 条 1.14 超低赔「蚊子肉」（周四004 黑山 / 周四005 英格兰）、2 条实证未跑赢定价（周四001 让胜超额 −0.7pt、周四003 让负 −8.5pt）。按既定「先有合格单场、才组合」「不硬凑、不低赔无脑选」原则，三档如实留空。这是证据门槛正常工作，不是没更新 —— 因此本次没有放宽任何门槛，改为把「已评估 / 为什么 0 档」明确显示出来。
