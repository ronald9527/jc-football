四、改造内容

1. 全站真实刷新状态机（triggerRePull() 重写）

① 全站同步：loadLiveDatasets() 拉云端 25+ 数据源 → renderAllTabs() 就地重渲染
             → 返回 receipt（覆盖模块数 / 失败项），明确弹「已全站同步 N 个模块」
② 通道探测：GET /api/refresh?health=1  （该分支绝不触发 CI；未就绪即如实收尾）
③ 真实触发：POST /api/refresh，读取 ok / runId / error，不再吞错
④ 真实轮询：GET /api/refresh?run_id=... 拿 conclusion + 比对 version.json 的 deployTime
             → 新部署出现 → 再全站同步一次 → 「云端全量刷新完成」
             → 运行失败 / 取消 / 超时 / 无新部署 → 分别如实说明
⑤ 全程按钮阶段文案 + 诚实回执；失败不假装成功，成功必有证据

关键边界（必须讲清楚）：抓取 / 预测 / 提取 / 赛果回溯 / 结算全部在云端流水线（GitHub Actions）执行，浏览器做不到；浏览器真实做到的是「秒级同步云端全部产物 + 全站重渲染」与「真实发起云端全量流水线并核对结果」。报告不混淆这两件事。

另去掉无条件 setTimeout(__hardReload, 2600)：它会打断轮询状态机并让页面闪一下，而就地全站重渲染已满足「全站 tab 内容更新」。仅当云端 pageVersion 与本页不同时提示重开获取新版页面代码。

2. 浏览器实测发现并补修的竞态

首轮 Playwright 实测暴露一个真问题：主路径要拉 25+ 个 JSON，云端通道却可能几百毫秒就返回失败，① 已全站同步 的延迟 toast 会覆盖最终的「发起失败」回执，用户只看得到「正在发起刷新」——又变成不诚实。已加 finalShown 优先级：最终回执一旦落地，任何延迟的阶段提示都不再覆盖。同时把回执模块数从 8 补准为 9（此前漏计竞彩篮球）。

七、边界说明

  • 浏览器不能凭空抓到比云端更新的数据；按钮的职责是「把云端已部署的全部产物秒级同步到手机」+「真实发起云端全量流水线并核对结果」。若上游停更，按钮会如实说明「本次未产出新部署」，不会伪造时间。
  • 云端 CI 在海外对中国竞彩官方接口常被拦（本轮实测 completed failure），.ci_official_down 守卫会跳过部署保护生产；本地全量流水线与自动保鲜任务才是数据推进的主路径。
  • 推荐门槛一个都没放宽：赔率 1.60~3.20、实证超额≥0、样本≥20、非平局、真实 EV、同竞彩批次；「今日无推荐」是宁缺毋滥的正常结果。
  • 版本 v1.7.136 由部署脚本按模板哈希自动升版产生，随后已把网页、CHANGELOG、自检断言、AndroidManifest、APK 全部对齐到同一版本，并同步模板指纹，避免再次误升。
