二、五层根因链条

① 系统时钟漂移 —— 总病根

沙箱休眠 / 恢复后系统时钟可能比真实北京时间慢数小时。fetch_daily.py 用 time.strftime("%Y-%m-%d") 判定「竞彩当天」、用 time.time() 判定「是否已开赛」，于是真实已是 周五 11-13 却仍算 周四 11-12；周四场次凌晨 01:00 已开赛，还被当成未开赛塞进候选池。主批次排序又把「有推荐」排在「当天」之前，进一步偏离用户「我需要的是竞彩当天开出的赛程」。

② 资格判定顺序错误 —— 合格单场被提前丢掉

每场只保留唯一「系统意见」，旧实现先按后验把握度挑（必然是 1.1x 低赔正路），之后才判资格（赔率 1.6~3.2 / 实证超额≥0 / 样本≥20 / 非平局）。低赔必然因「蚊子肉」出界，而同场真正合理的中赔选项在选意见时已被丢弃，根本没机会进候选池。

③ 让球统计口径稀疏 + 贝叶斯后验被硬切

让球玩法按「盘口线 + 方向」统计历史，样本实测只有 1~17 场；而 _posterior() 在 n < 20 时直接 return market, 0.0，整段丢弃实证信息——与它自己设计的贝叶斯收缩（_PRIOR_N 本就是为小样本准备的）自相矛盾。结果所有中赔让球选项 edge 恒为 0，又被 empN≥20 挡掉。此外 hhadProb / hadProb 缺失时旧代码把「没数据」当成「概率 0」，按 d_prob<10 一刀切。

④ 推荐门槛双标 —— 达标组合被旧口径挡光

代码注释已明确「模型口径 joint_p 不能再当推荐标准、判定统一用后验连乘 combo_hit」，但硬门槛仍写着 if joint_p < min_joint: continue。实测稳健档 joint 0.164 < 0.20 被拒，而同源后验 0.238、真实 EV +7.9% 完全达标。这是「天天 0 档」的最后一环。

⑤ V站 信息从未进入比分预测数据源

score_predict.json 自身零 V站 字段，页面只能靠 BUILT_VZHAN 按竞彩编号 + 队名翻译做跨数据集拼接。编号反查 / 翻译 / 日期容差任一失配，或用户看「日期回溯」、用离线 APK，V站 信息就整体消失。另有主路径本地补全把含日期的 kickoff 二次拼成非法 ISO（11 条），以及 V站 合并因队名前缀 / 日期容差重复匹配（6/5）。
